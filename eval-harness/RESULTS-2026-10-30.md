## Grader and harness fixes (each one a mis-measure, not a skill failure)

1. `convai-reactivate-old-leads/states-dnd-skip`: the regex took only "do not disturb" with spaces. A run that wrote
   "Do-not-disturb contacts are skipped" failed it. Now `do[- ]not[- ]disturb`. That run's own text is matched by the
   new pattern (checked offline). Re-run: 5/5 on that grader.
2. `convai-switch-to-claude/roster-before-update`: `tool_order` takes `before`/`after`, not `sequence`. The case failed
   to load, so the first sweep ran without it (the log named the one load failure). Earlier, a load check run with a
   filter that matched no case had passed it, because that path hides load errors (README → Run). Fixed, then run 5×.
3. The pilot's `raw_request` (fixed "no data") and the single-agent `update_convai_agent`/`set_convai_outbound` became
   model-played responders covering four fixture agents. The bundle moved to the real item shape. The pilot's
   hand-written hint `note: "outboundArmed is false only because mode is off…"` was removed because the real tool emits
   no such note. `convai-turn-bot-on` still passed 5/5 without it.

### Skill changes (skill suite)

1. **`ghl-conversation-ai/SKILL.md` → "Confirm before anything goes live", the mode bullet:** added "Before proposing any
   mode change, read the agent's outbound state with `get_ai_configuration_bundle` (`item.outbound`, `outboundArmed`; the
   agent read does not carry them) and name each enabled trigger and what fires it (for `contact_tag`, the tag names)".
   Reason: on neutral mocks the current skill's turn-bot-on pilot (1 run, 0.43) never called the bundle. It tried raw

   3/3, then 5/5. Round 1 of 3; no other case needed a skill change. `convai-wave-skills.test.mjs` +
   `rail-ledger-skills.test.mjs` 17/17, full suite 4017/4017, no rail-ledger block touched.

### Grader fixes (mis-measures)

1. `skill-convai-lead-form/says-why-not-executable`: the regex took only `captur`. A correct run wrote "nobody has ever
   recorded what its request looks like". Now `captur|recorded|request (body|shape)|request looks like|no body`.
2. `skill-convai-reactivate/campaign-facts`: the llm grader required an explicit causal sentence ("eligible because it
   has an enabled config") and failed 5/5 on runs that stated it as data ("outbound SMS is already switched on… it can
   already start conversations"). The eligibility and de-dup facts are now regexes (`states-eligibility`,
   `states-no-dedup`, checked offline on the saved messages: de-dup 5/5 current vs 0/3 pre-W5a; eligibility matched both,
   since the bundle shows the config) and the llm grader keeps the rest. Re-run: 0.96 current, 0.59 pre-W5a.
